# Catálogo de Tecnologias

## Objetivo

Manter tecnologias, versões, compatibilidades, breaking changes, boas práticas, vulnerabilidades e custo operacional para orientar escolhas.

## Fluxo

Fonte confiável → atualização → validação → registro de versão → análise de compatibilidade → recomendação no Blueprint → alerta de obsolescência.

## Dependências

Blueprint, custos, migração, segurança, catálogo de dependências e plataforma de IA.

## Critérios de aceitação

- [ ] Cada entrada possui data e fonte.
- [ ] Compatibilidade é relacionada à stack do projeto.
- [ ] Breaking changes geram impacto e recomendação.
- [ ] Tecnologia desatualizada não é sugerida sem justificativa.
