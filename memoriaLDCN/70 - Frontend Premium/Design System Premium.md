# Design System Premium

## Objetivo

Garantir consistência visual, acessibilidade, velocidade de composição e evolução segura da interface.

## Camadas

Tokens → primitives → componentes → padrões → layouts → experiências.

## Regras

- Componentes não definem cores arbitrárias.
- Estados são parte do contrato do componente.
- Acessibilidade e teclado são requisitos de base.
- Mudanças visuais relevantes passam por exemplos e regressão visual.

## Critérios de aceitação

- [ ] Toda tela usa componentes ou justifica exceção.
- [ ] Tokens possuem tema claro e escuro.
- [ ] Componentes têm documentação e exemplos.
