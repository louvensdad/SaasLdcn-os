# Refatoração inteligente

## Objetivo

Melhorar código existente sem alterar comportamento esperado, usando métricas e padrões aprovados pela organização.

## Capacidades

Reduzir complexidade, remover duplicação, aplicar Clean Architecture, DDD e SOLID, melhorar performance e reduzir memória.

## Fluxo

Diagnóstico → proposta de refatoração → estimativa de risco → diff → testes de regressão → benchmark → revisão → aplicação incremental.

## Dependências

Engenharia reversa, qualidade, Blueprint, biblioteca de padrões e sistema de versões.

## Critérios de aceitação

- [ ] Comportamento anterior possui cobertura ou evidência de preservação.
- [ ] Ganho alegado é medido.
- [ ] Mudanças grandes são divididas em etapas reversíveis.
- [ ] Débito técnico atualizado após a refatoração.
