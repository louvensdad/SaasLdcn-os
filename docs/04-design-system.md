# LDCN OS - Design System

## 1. Purpose

This document defines the official visual system for LDCN OS.

The design system must express a premium enterprise platform: intelligent, cinematic, minimal, and controlled. It is built to support a serious AI operating environment, not a decorative consumer app.

The visual identity must align with:
- enterprise cinematic intelligence
- Apple-level clarity
- Arc-like spatial polish
- Linear-like structure
- Jarvis-like subtle presence
- dark premium atmosphere
- futuristic but minimal composition
- elegant motion
- intelligent glow
- zero gamer UI

## 2. Visual philosophy

### 2.1 Clean first

Every screen must prioritize clarity, hierarchy, and readability before visual effect.

### 2.2 Cinematic subtle

Visual depth should feel intentional and restrained. The interface should have atmosphere without becoming dramatic or noisy.

### 2.3 Intelligent depth

Depth should be created through layering, contrast, blur, spacing, and glow discipline, not through heavy decoration.

### 2.4 Responsive elegance

The experience must remain refined across desktop, tablet, and mobile adaptation modes.

### 2.5 AI as living layer

AI presence should feel integrated into the system, not bolted on. It should behave like an active intelligence layer with subtle state changes, not an intrusive chatbot skin.

## 3. Color system

The color system must support a dark premium environment with clear semantic contrast.

### 3.1 Background palette

Backgrounds should use deep dark neutrals with slight tonal variation.

Recommended direction:
- base background: near-black neutral
- elevated background: slightly lighter dark surface
- canvas background: soft layered dark tone
- ambient background: subtle tinted darkness for depth

### 3.2 Surface palette

Surfaces should distinguish hierarchy without creating visual clutter.

Recommended direction:
- primary surface: dark slate
- secondary surface: muted graphite
- tertiary surface: softened elevated plane
- floating surface: glass-like dark overlay

### 3.3 Accent palette

Accents should feel intelligent, not loud.

Recommended direction:
- primary accent: cool electric blue
- secondary accent: cyan or ice blue
- premium highlight: restrained violet-blue only when needed
- interactive accent: luminous but controlled

### 3.4 Semantic colors

Semantic colors must be precise and calm.

Use:
- success: muted green
- warning: amber
- error: controlled red
- info: blue-cyan
- neutral: gray-blue

### 3.5 Glow system

Glow is a signature visual language in LDCN OS.

Rules:
- glow must be soft and localized
- glow should reinforce active states, not decorate everything
- glow must never overpower text or structure
- glow should appear around AI states, primary actions, selected surfaces, and key metric emphasis

### 3.6 Gradients

Gradients should be subtle and directional.

Rules:
- use dark-to-dark gradients for depth
- use accent gradients sparingly
- avoid rainbow effects
- avoid high-saturation multi-color gradients
- prefer smooth radial or linear ambient gradients

## 4. Typography

Typography must feel modern, sharp, and enterprise-safe.

### 4.1 Primary font

Use a clean high-legibility sans-serif as the main interface font.

The font must support:
- strong UI clarity
- readable dashboards
- premium product tone
- wide language support

### 4.2 Technical font

Use a monospace or technical face for:
- code-like content
- IDs
- statuses
- stack references
- metrics that require precision

### 4.3 Heading scale

Headings must create clear hierarchy without excessive size jumps.

Rules:
- large headings for major page states
- medium headings for sections
- compact headings for panels and cards
- avoid oversized display typography except in hero moments

### 4.4 Spacing rules

Typography spacing must preserve calm density.

Rules:
- generous line-height for body text
- compact but breathable headings
- avoid cramped labels
- avoid excessive tracking

### 4.5 Readability rules

Rules:
- never sacrifice readability for style
- avoid ultra-thin text
- avoid small text on low-contrast surfaces
- preserve legibility in motion and overlays

## 5. Layout system

The layout system must be structured, modular, and enterprise-oriented.

### 5.1 Sidebar structure

The sidebar is the navigation backbone of the platform.

Rules:
- fixed structural presence on desktop
- collapsible when needed
- clear section grouping
- minimal iconography noise
- active state must be obvious but elegant

### 5.2 Dashboard grid

Dashboards must use disciplined grid logic.

Rules:
- modular card grid
- strong vertical rhythm
- avoid asymmetric chaos
- prioritize signal over decoration
- metrics should align cleanly

### 5.3 Page containers

Page containers must maintain consistent width discipline.

Rules:
- content should not stretch excessively
- use controlled max-width where needed
- support full-width operational views when appropriate
- preserve breathing room at edges

### 5.4 Responsive breakpoints

The system must support responsive adaptation.

Recommended breakpoint behavior:
- desktop: primary experience
- tablet: compact adaptation
- mobile: minimal mode

### 5.5 Content spacing

Spacing must feel intentional and refined.

Rules:
- consistent vertical rhythm
- moderate panel separation
- avoid random whitespace
- avoid cramped enterprise density

## 6. Motion system

Motion must support clarity, state awareness, and cinematic polish.

### 6.1 Transitions

Transitions should be smooth, short, and purposeful.

Rules:
- use fast transitions for interaction feedback
- use slightly longer transitions for modal and state changes
- avoid abrupt visual jumps

### 6.2 Hover behavior

Hover states should feel tactile and restrained.

Rules:
- subtle lift
- soft glow increase
- minor border emphasis
- no exaggerated scaling

### 6.3 Inertia

Motion should have a sense of weight and composure.

Rules:
- avoid robotic snapping
- use eased movement
- allow subtle inertia in panels and overlays

### 6.4 Spring animations

Spring motion may be used for:
- panels
- dialogs
- AI presence states
- expansion and collapse

Rules:
- spring motion must be gentle
- never feel bouncy in a playful way
- keep motion premium and controlled

### 6.5 Loading states

Loading must always communicate progress or readiness.

Rules:
- use subtle skeletons or pulse states
- avoid generic spinner overload
- loading should feel integrated with the visual system

### 6.6 Cinematic motion

Cinematic motion is allowed when it supports product identity.

Use for:
- page entry
- command palette emergence
- AI state transitions
- key wizard transitions

### 6.7 Forbidden animations

Do not use:
- bouncing toy-like motion
- flashy neon effects
- endless spinning without meaning
- aggressive parallax
- overshooting transitions
- attention-grabbing motion loops

## 7. Glassmorphism rules

Glass effects may be used, but only with discipline.

### 7.1 Blur intensity

Blur should be moderate and controlled.

Rules:
- use enough blur to create depth
- avoid extreme blur that harms readability
- prefer soft separation over heavy frosted noise

### 7.2 Transparency

Transparency must remain restrained.

Rules:
- use partial transparency on overlays and floating surfaces
- keep content readable
- never use transparency as decoration alone

### 7.3 Border opacity

Borders should be subtle and structural.

Rules:
- use low-opacity borders
- avoid strong outlines everywhere
- borders should support hierarchy, not dominate it

### 7.4 Shadow depth

Shadows should be layered and elegant.

Rules:
- use soft low-contrast shadows
- avoid giant shadow blobs
- shadows must support lift, not theatrical drama

## 8. Component rules

### 8.1 Buttons

Buttons must be clear, confident, and easy to scan.

Rules:
- one strong primary button style
- one restrained secondary style
- clear hover and active states
- no oversized cartoon buttons

### 8.2 Cards

Cards are the primary content containers.

Rules:
- modular and consistent
- subtle surface contrast
- strong internal spacing
- no bloated padding

### 8.3 Modals

Modals must feel precise and controlled.

Rules:
- clear focus
- soft overlay
- easy dismissal
- no cluttered modal content

### 8.4 Navigation

Navigation must be stable and predictable.

Rules:
- obvious active state
- clear hierarchy
- minimal visual noise

### 8.5 Wizard steps

Wizard steps must feel guided and progressive.

Rules:
- explicit progress
- calm transitions
- no dead-end steps
- strong feedback on completion

### 8.6 Tables

Tables must remain readable and operational.

Rules:
- compact but breathable
- strong alignment
- clear row hierarchy
- support scanning at speed

### 8.7 Metrics

Metrics must be legible and premium.

Rules:
- large enough to read instantly
- subtle supporting labels
- semantic color discipline

### 8.8 Forms

Forms must feel guided, not punitive.

Rules:
- clear labels
- immediate feedback
- safe error states
- adequate spacing

### 8.9 Inputs

Inputs must be calm and precise.

Rules:
- visible focus state
- strong contrast
- no noisy borders
- no cramped typing areas

### 8.10 Dropdowns

Dropdowns must feel like structured selectors, not floating noise.

Rules:
- clean spacing
- clear keyboard navigation
- controlled elevation

### 8.11 Command palette

The command palette is a premium interaction surface.

Rules:
- highly legible
- fast to open
- strong search behavior
- subtle cinematic reveal
- feels like a control surface, not a dropdown

## 9. LDCN presence layer

The LDCN presence layer is the visual representation of the AI operating intelligence.

### 9.1 AI orb

The AI orb is the core presence element.

It represents:
- active intelligence
- system attention
- conversational readiness
- voice and reasoning state

### 9.2 Voice states

The presence layer must visually communicate voice status.

States:
- idle
- listening
- thinking
- speaking

### 9.3 Listening animation

Listening should feel sensitive and active.

Rules:
- subtle pulse
- controlled glow expansion
- no chaotic movement

### 9.4 Thinking state

Thinking should feel deliberate and intelligent.

Rules:
- slower internal movement
- calm glow shifts
- restrained visual complexity

### 9.5 Speaking state

Speaking should feel expressive but contained.

Rules:
- rhythm-based motion
- subtle light modulation
- avoid aggressive audio-visual effects

### 9.6 Idle state

Idle should feel alive but quiet.

Rules:
- minimal motion
- soft ambient presence
- no dead static feeling

### 9.7 No humanoid 3D initially

The platform must not introduce a humanoid 3D avatar at the initial stage.

The first version of the presence layer must remain abstract, elegant, and lightweight.

## 10. UX principles

### 10.1 No dead clicks

Every interactive action must provide feedback or clear state change.

### 10.2 Every action gives feedback

The user must always understand that the system has registered the action.

### 10.3 Contextual transitions

Transitions should explain what changed and why.

### 10.4 Minimal friction

The interface should remove avoidable steps and visual friction.

### 10.5 Keyboard-first future

The design must support a future where command and navigation can be driven efficiently by keyboard.

### 10.6 Responsive-first

Interaction quality must remain strong across device sizes.

## 11. Responsive rules

### 11.1 Desktop first

Desktop is the primary canvas for LDCN OS.

### 11.2 Tablet adaptation

Tablet should preserve core productivity with reduced density and compact navigation.

### 11.3 Mobile minimal mode

Mobile should focus on essential operations, status viewing, and lightweight actions.

### 11.4 Collapsible sidebar

The sidebar must collapse gracefully to preserve usable content space.

## 12. Visual anti-patterns

The following must not exist in LDCN OS:
- bootstrap look
- random neon
- giant shadows
- inconsistent spacing
- oversized cards
- generic admin layouts
- too many borders
- uncontrolled animations
- toy-like styling
- visual clutter without purpose

## 13. Accessibility

Accessibility is a core quality requirement.

### 13.1 Contrast

Text and interface elements must maintain usable contrast across all major states.

### 13.2 Focus states

Focus states must be visible, elegant, and consistent.

### 13.3 Keyboard navigation

The interface must support keyboard-driven navigation for key workflows.

### 13.4 Reduced motion support

Motion must respect user preferences and degrade gracefully when reduced motion is requested.

## 14. Design tokens future

The design system should eventually centralize tokens for:
- spacing
- colors
- radius
- motion
- z-index
- shadows

These tokens must become the single source of truth for future UI implementation.

## 15. Final rule

The design system must always preserve the LDCN identity: premium, dark, intelligent, minimal, and controlled.

If a visual choice makes the product louder, cheaper, or less trustworthy, it does not belong in LDCN OS.
